# ADR-003: Multi-Repo Read-Only Privacy Boundary, Strict Allowlists, and Dry-Run Dispatch Gate

- **Status:** Accepted
- **Date:** 2026-11-22
- **Governance & Standards:** `POP_T_154 (Cross-Repo IP Shielding & LGPD)`, `POP_T_009 (.env Isolation)`, `POP_B_179 (TickTick Bridge)`, `OWASP LLM01`, `Zero-Trust Human Gate`

## Context

`ops-sla-telemetry-lakehouse` serves two distinct operational scopes:
1. **Public Portfolio Lakehouse (`github.com/jhsfhtls/ops-sla-telemetry-lakehouse`):** Demonstrates event-driven CDC, Medallion DuckDB/Parquet processing, dbt incremental modeling, and SRE observability using deterministic synthetic data.
2. **Local C.O.R.E. Control Tower (`POP_T_048` / `POP_T_066`, Consulting Phase 8 SRE):** Aggregates operational health and SLA deadlines across four local repositories (`core`, `operations`, `career`, `studies`) and can dispatch alerts or high-priority tasks via `notify.py` and `ticktick_client.py`.

Exposing private consulting client workspaces (`operations/Clientes/`), personal career applications (`career/`), study materials (`studies/`), free-text agent notes, or `.env` secrets inside a public repository or unguarded external webhook would violate `POP_T_154`, `POP_T_009`, and LGPD minimization principles.

## Decision

We enforce a strict Zero-Trust privacy and execution boundary between the public codebase and local C.O.R.E. telemetry:

1. **Public Repository Contains Only Synthetic Data (`seed=42`):**
   - Every committed fixture, simulator dataset (~50,000 synthetic field orders with `seed=42`), dbt seed, test case, and documentation artifact in `ops-sla-telemetry-lakehouse` is 100% synthetic.
   - No client names, company names, sponsor names, file paths from `operations/Clientes/`, study notes, or `.env` values may ever be committed or referenced in the public repository.

2. **Read-Only Local Multi-Repo Collectors with Closed Per-Source Field Allowlists:**
   - Multi-repo collectors run exclusively locally in **read-only** mode and enforce a **closed allowlist** per data source (unlisted fields are never extracted, logged, or persisted):
     - **`core/.logs/agent_telemetry.jsonl`:** Allow **only** `timestamp_utc`, `trace_id`, `span_id`, `skill`, `model`, `provider`, `tokens_total`, `cost_usd`, `duration_ms`, `status`, `repo`. Exclude free-text `notes` and `operation`.
     - **`core/docs/**/POP_*.md`:** Allow **only** `pop_id`, `relative_path`, `last_reviewed`, `age_days`, `status` (freshness classification aligned with `governance_cron.py`). Never read or persist POP body prose.
     - **`core/.agents/state/consulting_pipeline.json`:** Allow **only** opaque/hashed `id`, `fase_atual`, `status`, `data_abertura`, `data_entrada`. Explicitly drop `cliente`, `nome`, `setor`, `segmento`, `sponsor`, `proxima_acao`, `next_action`, and `path_jornada`. Never read `operations/Clientes/`.
     - **`core/.agents/state/career_pipeline.json`:** Allow **only** opaque/hashed `id`, `data_aplicacao`, `status`. Explicitly drop `empresa`, `vaga`, `proxima_acao`, and `artifact_folder`.
     - **`studies/.agents/memory/srs_state.json`:** Allow **only** opaque/hashed `card_id`, `last_reviewed`, `next_review`, `interval`, `review_count`, `last_result`. Never read study markdown content or question/answer payloads.
   - Mutable or descriptive source IDs (`id`, `card_id`) are converted into opaque salted/non-reversible code identifiers (`sha256` prefix) when materialized in telemetry snapshots so no entity name leaks through identifier naming.

3. **Physical Storage Isolation (`core/.logs/ops_sla_telemetry/`):**
   - Real local telemetry snapshots, Bronze/Silver artifacts derived from C.O.R.E. repositories, and dispatcher state generated by multi-repo collectors are written **exclusively** outside the public repository tree to `core/.logs/ops_sla_telemetry/` (protected by `core/.logs/.gitignore`).
   - Additionally, `ops-sla-telemetry-lakehouse/.gitignore` enforces the `AI SATELLITE SHIELD` alongside `data/`, `.logs/`, `.state/`, and `.env` rules as defense in depth.

4. **Safe External Dispatcher Contract (`--dry-run` Default + Human Gate):**
   - Integration with `core/scripts/agent_tools/ticktick_client.py` (targeting canonical project `00_INBOX_AGENTES`, priority `5` High per `POP_B_179`) and `notify.py` uses decoupled optional adapters so `ops-sla-telemetry-lakehouse` remains 100% standalone when cloned externally.
   - The dispatcher defaults strictly to `--dry-run` (simulated JSON/Markdown preview), applies idempotent deduplication keys per `(incident_key, severity)`, enforces a hard `max_alerts_per_run` ceiling, and refuses any external HTTP/API write unless invoked explicitly with `--execute --confirm`.
   - Credentials remain isolated inside `.env` (never read, logged, or printed by agents; reports expose presence booleans only).
   - MCP server responses wrap external/untrusted textual descriptions in `<untrusted_data>` delimiters (`OWASP LLM01`).

## Consequences

- **Positive:**
  - Safe dual-purpose operation: anyone can clone and run the public lakehouse offline in < 60s on synthetic data, while the local maintainer gains a unified C.O.R.E. SLA control tower with zero PII leakage risk.
  - Automated property and unit tests can formally prove that fields outside the allowlist are never read into output schemas.
- **Trade-offs:**
  - Operational alerts inside the lakehouse reference opaque entity codes (`OPS-CON-<hash>`, `CAR-<hash>`, `SRS-<hash>`) rather than raw client/company names; human operators map opaque codes back locally when triaging in `00_INBOX_AGENTES` or private workspaces.

## Verification Criteria

- Collector unit tests feed synthetic payloads containing forbidden keys (`cliente`, `sponsor`, `empresa`, `vaga`, `proxima_acao`, `path_jornada`, `notes`) and verify 0 forbidden keys or values appear in emitted records or files.
- Dispatcher tests verify `--dry-run` default behavior, refusal to execute externally without `--execute --confirm`, idempotent alert suppression for repeated incident keys, and `max_alerts_per_run` enforcement.
- `check_secrets.py` and `.gitignore` shield audits pass with zero warnings across all commits.
